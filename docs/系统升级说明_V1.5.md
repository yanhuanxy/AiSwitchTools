# 系统升级说明文档 V1.5 (本次改造)

## 1. 概述
本次升级（V1.5）主要完成了 **Coze 风格智能体平台的基础架构搭建**。核心目标是引入“工作流”与“知识库”的实体定义，并升级前端界面以支持可视化编排。虽然目前尚未实现后端的执行逻辑，但已为 V2.0 的运行时打下了坚实的数据与交互基础。

## 2. 改造点详细说明

### 2.1 数据库架构升级 (Schema Evolution)
**做了什么？**
- 新增 `Workflow` 表：存储工作流名称、描述及核心的 `graphData` (JSON 结构，保存画布的节点与连线)。
- 新增 `KnowledgeBase`, `Document`, `Chunk` 表：构建完整的 RAG 数据模型，支持从知识库到文档再到切片的三级层级。
- 升级 `CharacterVersion` 表：新增 `workflowId` 和 `knowledgeBaseId` 外键。

**为什么这么做？**
- **解耦设计**：将工作流和知识库设计为独立实体，而非 Agent 的附属属性，这样同一个工作流/知识库可以被多个 Agent 复用。
- **数据驱动视图**：直接将前端 VueFlow 的图数据存储为 JSON，避免了过度设计后端节点表结构，大幅降低了初期开发成本，提升了灵活性。

### 2.2 后端模块扩展 (Backend Modules)
**做了什么？**
- 创建 `WorkflowModule`：实现了工作流的 CRUD 接口。
- 创建 `KnowledgeBaseModule`：实现了知识库的基础管理接口。
- 改造 `CharacterVersionsService`：在创建/更新 Agent 版本时，支持接收并存储关联的 `workflowId` 和 `knowledgeBaseId`。

**优点**：
- **职责单一**：新模块独立于原有的 Chat/Character 逻辑，互不干扰。
- **接口规范**：统一使用 DTO 进行参数校验，保证了数据的完整性。

### 2.3 前端可视化重构 (Frontend Visualization)
**做了什么？**
- 引入 `@vue-flow/core`：集成了专业的流程图库。
- 新增 **工作流编辑器** (`WorkflowEditorPage`)：支持拖拽、缩放、小地图等画布操作。
- 新增 **资源管理页面**：工作流列表页与知识库列表页。
- 升级 **导航系统**：在顶部菜单添加了新功能的入口。

**优点**：
- **所见即所得**：用户不再面对枯燥的表单，而是通过直观的图形化界面进行编排。
- **高扩展性**：基于 VueFlow，未来可以轻松扩展自定义节点组件（如 LLM 节点卡片）。

## 3. 架构图解 (Current Architecture)

本次改造主要集中在 **配置态 (Configuration Phase)** 的链路打通。

```mermaid
graph TB
    subgraph Frontend [客户端 (Vue3 + VueFlow)]
        FE_Workflow[工作流编辑器] -- graphData JSON --> FE_API[API Client]
        FE_KB[知识库管理页] -- create/upload --> FE_API
        FE_Agent[角色编排页] -- bind workflow/kb --> FE_API
    end

    subgraph Backend [服务端 (NestJS)]
        FE_API -- HTTP POST/PATCH --> API_Gateway[Controller Layer]
        
        API_Gateway --> WF_Svc[Workflow Service]
        API_Gateway --> KB_Svc[KnowledgeBase Service]
        API_Gateway --> CV_Svc[CharacterVersion Service]
        
        WF_Svc -- Save JSON --> DB[(SQLite)]
        KB_Svc -- Save Meta --> DB
        
        CV_Svc -- Link IDs --> DB
    end

    subgraph Database [数据模型]
        T_WF[Table: Workflow]
        T_KB[Table: KnowledgeBase]
        T_CV[Table: CharacterVersion]
        
        T_CV -.->|FK| T_WF
        T_CV -.->|FK| T_KB
    end
```

## 4. 优缺点分析

### 优点
1.  **开发效率高**：通过存储 JSON Blob (`graphData`) 快速实现了画布的保存与读取，避免了复杂的图数据库建模。
2.  **体验升级**：前端可视化能力显著提升，从纯文本配置迈向了图形化编排。
3.  **非侵入式**：新增功能未破坏原有 Chat 和 Character 的核心逻辑，系统稳定性有保障。

### 缺点 (待改进)
1.  **缺乏校验**：目前后端仅保存 JSON 字符串，未对节点连接的合法性（如是否有环、输入输出类型匹配）进行校验。
2.  **仅配置态**：工作流和知识库目前只是“静态数据”，尚未接入 Chat 流程真正执行（这是 V2.0 的重点）。
3.  **大字段风险**：随着工作流变复杂，`graphData` 字段可能变得很大，SQLite 读取可能存在性能瓶颈（未来可考虑分离存储）。

## 5. 总结
V1.5 版本成功搭建了 **Agent 编排平台** 的骨架。我们现在拥有了“躯壳”（界面与数据结构），V2.0 将注入“灵魂”（执行引擎与向量检索），届时系统将具备真正的智能体能力。
