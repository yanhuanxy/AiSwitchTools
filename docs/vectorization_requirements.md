# 功能清单验证与缺失对比表 (Verification & Requirements)

## 1. 现状审查 (Current State Review)

目前 `RagService` 的实现仅包含基础的文本向量化功能：
- **支持格式**: 仅纯文本 (Buffer -> String)。
- **不支持**: PDF, Word (.docx), Markdown (结构化), HTML。
- **预处理**: 仅简单的固定长度切分 (`chunkText` 方法)，无清洗、无语义切分。
- **向量化**: 依赖 `LlmService` 调用外部 API。
- **存储**: LanceDB `chunks` 表。

## 2. 缺失功能对比表 (Gap Analysis Table)

| 模块 | 功能名称 | 优先级 | 业务影响 | 技术复杂度 | 状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **预处理** | **PDF 解析** | **P0** | 无法处理用户上传的最常见文档格式，阻塞核心业务。 | 中 (依赖 `pdf-parse`) | ❌ 缺失 (待集成) |
| **预处理** | **Word (.docx) 解析** | **P0** | 无法处理办公文档，影响企业级场景。 | 中 (依赖 `mammoth`) | ❌ 缺失 |
| **预处理** | **文本清洗** | **P1** | 包含乱码、多余空格、页眉页脚会降低检索准确率。 | 低 | ❌ 缺失 |
| **分块** | **智能分块** | **P1** | 简单的固定字符分块会切断语义，导致回答质量差。 | 中 (需实现 RecursiveCharacterTextSplitter) | ⚠️ 简单实现 |
| **向量化** | **批量向量化** | **P1** | 逐条 API 调用效率低，易触发限流。 | 低 | ❌ 缺失 |
| **存储** | **Metadata 增强** | **P2** | 缺乏页码、文件名等元数据，无法在引用中展示来源。 | 低 | ⚠️ 部分支持 |
| **监控** | **解析日志与监控** | **P2** | 失败无法排查，无性能指标。 | 低 | ❌ 缺失 |

## 3. 产品确认 (Product Verification)

- **PDF/Word 解析**: 确认为 MVP 必须包含的功能。
- **智能分块**: 建议在本次迭代中优化，使用基于分隔符的递归切分。
- **实现顺序**: 
  1. 引入解析库 (PDF/Word)
  2. 实现清洗与标准化
  3. 优化分块逻辑
  4. 批量向量化 API

## 4. 最终需求总结

本次开发将聚焦于构建一个健壮的 **DocumentProcessor** 模块，支持多种格式的解析、清洗和智能分块，并无缝集成到现有的 `RagService` 中。
