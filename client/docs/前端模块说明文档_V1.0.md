# 角色扮演 AI 对话平台｜前端模块说明文档 V1.0

- 版本：V1.0
- 日期：2026-01-29
- 描述：本文档旨在梳理前端代码结构，按照业务功能进行模块化拆解，帮助开发者快速理解项目架构与代码组织。

---

## 1. 项目架构概览

### 1.1 技术栈
- **核心框架**：Vue 3 (Composition API) + TypeScript
- **构建工具**：Vite
- **状态管理**：Pinia
- **路由管理**：Vue Router 4
- **UI 组件库**：Element Plus
- **网络请求**：Axios (REST) + EventSource (SSE)
- **代码规范**：ESLint + Prettier

### 1.2 目录结构树
```text
src/
├── components/        # [通用/业务] UI 组件
├── pages/             # [页面] 路由级页面组件
├── router/            # [路由] 路由定义与守卫
├── services/          # [服务] API 接口封装
├── stores/            # [状态] Pinia 状态管理
├── styles/            # [样式] 全局样式
├── types/             # [类型] TypeScript 类型定义
├── utils/             # [工具] 纯函数工具
├── App.vue            # 根组件
└── main.ts            # 入口文件
```

## 2. 业务模块详解

本项目按照 **“业务领域”** 逻辑，将代码分散在各技术分层中。以下是各核心模块的映射关系：

### 2.1 认证模块 (Auth Module)
负责用户的登录、绑定、凭证管理及全局拦截。

| 层级 | 文件/位置 | 职责 |
| :--- | :--- | :--- |
| **Pages** | `pages/AuthBindPage.vue` | 账号绑定页面 (Magic Link 输入) |
| | `pages/MagicLinkCallbackPage.vue` | 魔法链接回调落地页 |
| **Store** | `stores/auth.ts` | 管理 Token (Access/Refresh)、当前身份、登出逻辑 |
| **Service** | `services/auth.ts` | 登录、刷新 Token、绑定 API 接口 |
| **Global** | `App.vue` | 包含“退出登录”全局入口 |
| **Utils** | `services/api.ts` | Axios 拦截器中处理 Token 注入与 401 自动刷新 |

**关键流程**：
- **自动刷新**：API 拦截器捕获 401 -> 暂停请求 -> 调用 refresh -> 重发原请求。
- **登出**：调用 API -> 清除 Store -> 切换为匿名 Token。

### 2.2 角色模块 (Role Module)
负责角色的 CRUD、版本管理及 Prompt 配置。

| 层级 | 文件/位置 | 职责 |
| :--- | :--- | :--- |
| **Pages** | `pages/RolesPage.vue` | 角色列表页 (首页) |
| | `pages/RoleDetailPage.vue` | 角色详情页 (含版本列表) |
| | `pages/RoleCreatePage.vue` | 创建角色表单 |
| | `pages/RoleEditPage.vue` | 编辑角色表单 |
| **Components** | `components/RoleCard.vue` | 列表中的角色卡片组件 |
| **Store** | `stores/roles.ts` | 缓存角色列表、当前选中角色数据 |
| **Service** | `services/roles.ts` | 角色增删改查 API |
| **Utils** | `utils/promptConfig.ts` | Prompt 配置结构的默认值生成 |

**设计特点**：
- **版本控制**：编辑操作实际上是创建/修改 Draft 版本，发布后生成新的 Version。

### 2.3 对话模块 (Chat Module)
核心业务模块，负责消息流转、SSE 连接、任务控制。

| 层级 | 文件/位置 | 职责 |
| :--- | :--- | :--- |
| **Pages** | `pages/ChatPage.vue` | 对话主容器，协调各子组件与 Store |
| **Components** | `components/MessageList.vue` | 消息列表容器 |
| | `components/MessageItem.vue` | 消息气泡 (Markdown 渲染 + 图片展示) |
| | `components/Composer.vue` | 输入框 (文本 + 图片上传) |
| | `components/AttachmentStrip.vue` | 待发送附件预览栏 |
| | `components/TaskControls.vue` | 停止/重试/继续 按钮组 |
| **Store** | `stores/chat.ts` | 管理当前会话的消息流、SSE 缓存、生成状态 |
| | `stores/conversations.ts` | 辅助管理当前会话元信息 |
| **Service** | `services/chat.ts` | 发送消息、任务控制 API |
| | `services/sse.ts` | SSE 连接封装 (EventSource) |
| | `services/attachments.ts` | 图片上传 API |

**核心机制**：
- **流式渲染**：`ChatPage` 监听 SSE -> 更新 `chatStore` -> `MessageItem` 实时渲染 Markdown。
- **分页加载**：利用 `nextCursor` 向前追溯历史消息，使用 `prepend` 方式合并数据。

### 2.4 历史模块 (History Module)
负责历史会话的浏览与导航。

| 层级 | 文件/位置 | 职责 |
| :--- | :--- | :--- |
| **Pages** | `pages/HistoryPage.vue` | 历史会话列表页 |
| **Store** | `stores/conversations.ts` | 管理会话列表数据、分页游标 |
| **Service** | `services/conversations.ts` | 获取列表、删除会话 API |

## 3. 公共机制与规范

### 3.1 错误处理
- **统一工具**：`services/error.ts`
- **使用方式**：
  ```typescript
  try {
    // 业务逻辑
  } catch (e) {
    // 解析错误码并返回用户友好的消息
    const msg = handleError(e, "默认错误提示", "context.tag")
  }
  ```
- **UI 反馈**：根据场景使用 `ElMessage` (轻量) 或 `el-alert` (持久)。

### 3.2 路由与导航
- **定义**：`router/index.ts`
- **规范**：
  - 页面组件统一放在 `src/pages`。
  - 路由路径尽量扁平，参数使用 props 传递。

### 3.3 类型系统
- **定义**：`types/index.ts`
- **规范**：所有 API 响应、核心领域模型 (Role, Message, User) 必须定义 TypeScript 接口。

## 4. 开发建议

1.  **新增功能时**：
    - 先定义 `types`。
    - 在 `services` 中添加 API 调用。
    - 在 `stores` 中添加状态管理 (Action)。
    - 在 `pages` 或 `components` 中实现 UI。
2.  **组件拆分原则**：
    - 如果一个组件超过 300 行，考虑拆分。
    - 通用 UI 逻辑 (如特定样式的 Card) 提取到 `components`。
    - 业务逻辑尽量下沉到 `stores` 或 `hooks` (目前主要在 Store)。
